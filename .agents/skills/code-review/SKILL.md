# 独立レビュー

## 使用条件
第三者としてのレビュー、再レビュー。実装と別セッションで行う。同一セッションなら自己確認と明記する。

## 参照資料
[作業フロー](../../../docs/quality/workflow.md)、[レビュー書式](../../../docs/quality/review-template.md)、[コード原則](../../../docs/quality/code-principles.md)、[品質基準](../../../docs/quality/standards.md)、関連仕様・計画・問題台帳。

## 入力
比較元と対象コミット、差分、計画、検証証跡。Git未配置なら対象ファイル一覧・SHA-256・比較差分を求め、特定できない範囲を未確認とする。

## 手順
1. 差分と関連経路・仕様を直接読む。実装担当の報告だけで判断しない。
2. 入力境界、部分失敗、解除、ブラウザ差、性能、保存互換性、テストの正解を調べる。
3. 必要な検証を自ら行う。生成物が出る場合は事前状態を把握し、ソースへ混入させない。
4. 根拠と再現条件のある指摘を重要度順にまとめ、推測は区別する。
5. 修正は実装担当へ戻し、更新対象と関連経路を再レビューする。

## 制約
明示的な修正許可なしにソース・設定・テストを変更しない。レビュー記録の保存は依頼範囲に従う。独立性を偽らず、検証不能を成功にしない。指摘解消のためだけに重要度を下げない。

## 完了条件
対象、指摘、検証、残存リスクが明確。Critical / Major / Minorや必須検証不足が残るならマージ可能と判定しない。指摘なしでも未検証を明記する。

## 出力形式
レビュー書式に従い、対象、独立性、重要度・位置・根拠・再現・影響・修正方針、検証、結論。最終承認は人間に残す。
