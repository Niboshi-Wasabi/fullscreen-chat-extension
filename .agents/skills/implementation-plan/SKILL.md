# 設計と実装計画

## 使用条件
複数モジュール、ブラウザ境界、保存互換性、ハーネスの変更。小さな文言修正には計画を強制しない。

## 参照資料
[構造](../../../docs/architecture/overview.md)、[契約](../../../docs/architecture/contracts.md)、[計画テンプレート](../../../docs/plans/TEMPLATE.md)、[品質基準](../../../docs/quality/standards.md)、[問題台帳](../../../docs/quality/issues.md)、関連要件。

## 入力
確認済み要件、変更範囲と制約、未決定事項、継続中の計画。

## 手順
1. コードから送受信側・起動/停止・保存・ブラウザ差を確認する。
2. 再利用を優先し、必要な場合だけ複数案とトレードオフを比較する。
3. テンプレートに目的、対象/対象外、変更対象、依存、手順、リスク、検証、完了条件を記述する。
4. 重要判断はADRに分離し、必要な人間の判断を具体化する。
5. 再開地点・進捗・未解決・証跡を残す。既存計画は読み直して更新する。

## 制約
未決定の数値をテスト基準にしない。未導入の検証は計画に記録する。計画作成は依存導入・公開の許可ではない。作成権限がなければ提案として回答する。

## 完了条件
次の担当が会話履歴なしに範囲、必要な判断、検証、完了条件を理解できる。未承認部分を区別する。

## 出力形式
計画、設計の要点、ADR参照、必要な判断、リスク、最初の実行可能な作業。
