## 判定結果（確定）

**自前コアで新規実装する（greenfield）。**  
近い OSS は **仕様・実装パターンのリファレンス** とし、製品全体の fork はしない。

MIT の Stream Danmaku Overlay については、必要箇所のみ **着想・アルゴリズムの参考** または **明示的に帰属した小さな移植** を検討可。リポジトリ丸ごとの fork は採用しない。

## ゲート適用

### fork / 移植を選ぶ条件（プラン）

> スコア上位の OSS があり、ライセンスが許容、YT+Twitch 基盤またはパネル基盤が流用でき、足りない体験の過半が「差分追加」で埋まる

| 候補 | スコア帯 | ライセンス | 流用できる核 | 足りない体験の過半が差分で埋まるか |
|------|----------|------------|--------------|------------------------------------|
| Stream Danmaku Overlay | 中（表示は近い） | MIT | YT+Twitch 弾幕／積み上げ、隠し iframe 知見 | **否** — 投稿・NG横断・別窓・通常コメント・Firefox ストアが大規模追加 |
| Youtube Live Chat Fullscreen | 高（YT パネル） | **GPL-3.0** | ネイティブチャット流用、WXT、Firefox | **否** — Twitch・弾幕・通常コメントを足すと別製品化。GPL は配布方針を拘束 |
| YoutubeLiveChatFlusher | 高（弾幕） | 要確認（利用時再確認） | 弾幕・Banned Words | **否** — YT専用、投稿パネル統合が別問題 |
| Yochatto | 最高（Twitch UX） | 非 OSS | なし（仕様参考のみ） | fork 不可 |

**過半が差分追加で埋まる候補は存在しない** → fork 条件を満たさない。

### 自前を選ぶ条件（プラン）

> 横断＋通常コメント＋投稿を足すと既存コアを壊す／ライセンスやアーキが合わない／メンテ不能

該当:

1. **横断 + 通常コメント + 投稿 + 3 モード** は、表示専用コアにも、YT パネル専用コアにも、破壊的拡張になる
2. **GPL-3.0** ベースを取り込むとストア公開製品全体が GPL になりやすい（方針として避け、MIT 想定の自前コアにする）
3. 非 OSS の Yochatto は法的に流用不可

→ **自前条件を満たす**

実装時に読む・真似る（コピーする場合はライセンス遵守と帰属）。

| 優先 | ソース | 学ぶこと |

| 4 | Yochatto（仕様のみ） | Twitch 全画面／フローティング窓の UX 水準 |
| 5 | Youtube Comment Viewer（仕様のみ） | 通常コメント全画面の体験ベンチマーク |

## 実装時の方針（次プランへの引き継ぎ）

1. **新規リポジトリ**で Manifest V3 + TypeScript。ビルドは **WXT**（または同等の Chrome/Firefox 両対応ツール）を第一候補とする
2. Core（Normalize / Filter / Router / Views）は自前
3. Adapter はサイトごとに分離（`youtube-live` / `youtube-comments` / `twitch`）
4. 投稿はネイティブ UI 再利用を優先（YLCFS のアプローチを参考）
5. 弾幕・受信継続は Stream Danmaku の知見を検証したうえで自前実装
6. 外部コードをまとまった量で取り込む場合は、ファイル単位でライセンスと帰属を `THIRD_PARTY.md` に記録する
7. 実機評価で「特定 MIT モジュールをほぼそのまま使う方が明らかに正しい」となった場合のみ、本判定を部分改訂する（製品全体の fork には戻さない）

## 判定サマリー（1 ページ用）

| 項目 | 内容 |
|------|------|
| 決定 | **自前（greenfield）** |
| 理由 | 統合要件が既存単一 OSS の差分規模を超え、有力パネル実装が GPL、Twitch UX 王者が非 OSS |
| しないこと | 製品全体の fork、GPL コードの無断混在、非 OSS のコード流用 |
| すること | 公開仕様・アーキの学習、MIT なら帰属付きの限定移植を許容 |
| 次のアクション | 実装プラン作成 → 骨格（WXT・Adapter スタブ・3 View 空UI）→ サイト順に縦通し |
