# Phase 3: ローカル検証基盤

## 目的・背景

既存の型・両ビルドに、実際に失敗を検出する静的解析・回帰テスト・構造/文書/manifest/多言語検査を追加し、単一入口から実行する。ユーザーの2026-11-14「進めてください」に基づく後続作業。[全体計画](2026-11-14-harness-foundation.md)を参照。

## 対象範囲・対象外

Phase 3のローカル検証が対象。必要な固定版開発依存、設定、scripts、tests、関連文書を追加する。アプリの仕様変更、Git初期化、コミット/push、GitHub設定、ストア提出、有料利用、ブラウザE2Eは対象外。

## 設計・依存・判断

- Vitest + WXT公式連携、ESLint/TypeScript、Prettier、dependency-cruiser、YAML解析を採用。依存は固定しlockfileを保存。
- Nodeはツールが対応する22.13以降の22系、24系、26系以降を対象とし、実行環境22.23.2で検証する。ブラウザの最低対応版とは別の開発要件。
- 多言語の現在の不足はplayerToggleOn/Offの42言語。既存の英語フォールバックを維持する明示的な欠落リストを作り、新規欠落やキー/補間不一致を失敗させる。翻訳を捏造しない。
- manifestは現行の権限・通信先を回帰用スナップショットとして比較。要求への適合承認ではなく、ISS-001等の公開前判断は維持する。
- フォーマット初期導入で既存ソースに変更が必要なら、書式だけと分かるよう記録し、不要な機能修正は混ぜない。

## 変更対象・手順

1. 現行チェックとコードの挙動を確認し、依存を導入。
2. lint/format/依存制約の設定と検査スクリプトを追加。
3. ロジック・保存API結合・検査器の負例を追加。
4. WXT prepare、文書/locale、format/lint、型、テスト、依存、両ビルド、manifestの順に統合。
5. 失敗例と全体実行を確認し、導入状態・課題・証跡を同期。

## リスク・復旧

新しいツールのNode/peer互換性、既存lint違反、既存仕様の矛盾を区別する。セキュリティ設定の自動緩和を残さない。生成物と外部コピーを検査対象から分離する。作業前のソースは変更前にハッシュと一時コピーを保存し、機能変更を混ぜない。

## 検証・完了条件

空のテストを成功扱いせず、正の回帰と意図的な文書・locale・構造・manifest違反を検出する。統合入口は必須ステップ失敗で非ゼロ終了。両ビルド出力を実際に検査する。独立レビューとSkills実機検証は未実施として維持する。
