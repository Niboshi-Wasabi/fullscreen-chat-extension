# 開発ハーネスの段階導入

## 目的・背景

既存の全画面コメント拡張に、製品非依存の知識・作業・検証・レビュー基盤を追加する。既存PRD、実装、設定一覧、Cursorルールを再利用する。[ADR 0001](../decisions/0001-harness-foundation.md)を参照。

## 対象範囲・対象外

初回の作業範囲はPhase 0〜2の文書・Skills整備。ユーザーが提示した設計案の実装を2026-11-14に依頼。アプリ変更、依存導入、Git初期化、コミット・push、CI設定、ストア提出は初回に行っていない。後続依頼によるPhase 3は[別計画](2026-11-14-verification-foundation.md)で管理する。

## 要件・依存・判断

個人で開発し、GitHub で管理する。両ストアでの公開を予定し、当時は YouTube、ニコニコ生放送、Twitch を対象とした。Windows を優先し、macOS は今後検討する。TypeScript/WXT/pnpmを維持。有料導入は別途承認。

既存の仕様矛盾、Git配置、品質数値は[問題台帳](../quality/issues.md)の未決定事項として管理する。これらを今回の文書追加で解決したとは扱わない。

## 実装手順・変更対象

1. 既存ファイル・ルール・契約を読み、要件と矛盾を整理する。
2. AGENTSとdocsの正本を追加する。既存PRD・実装計画は改訂しない。
3. 汎用コード原則を共通文書へ、設定UIの既存本文をdocs/design/settings-ui.mdへ移す。
4. .agents/skillsの5 Skillsを追加し、Cursorルールは適用条件と参照に置換する。
5. README・デザイン索引から新しい入口へリンクする。
6. Skill構文・内部参照・役割制約・元ルールの保持を確認し、結果を記録する。

変更対象はAGENTS.md、README、.agents/skills、.cursor/rules、docs。src、public、scripts、package.json、lockfile、WXT/TS設定は保持する。

## リスク・復旧

文書の正本移動で参照切れ・原則欠落が起こり得るため、移した本文を保持しリンク検査する。新しい文書の存在は機械的品質保証ではない。Git未配置のため基点との差分を再構成できる範囲に限界がある。将来Git化したら対象コミットを証跡にする。

取り消す場合は今回の変更だけを対象とし、以後の編集を確認する。アプリや既存仕様の一括削除・上書きで戻さない。

## 進捗・検証証跡

2026-11-14: 初期ファイルと5 Skillsを追加。既存Cursor原則を共通文書へ整理し、設定UI本文を移した。依存導入・アプリ変更・Git操作は行っていない。

検証対象は追加・更新した28ファイル。Skill Creatorのquick_validate.pyをUTF-8モードで5 Skillsそれぞれに実行し、すべて終了コード0。内部リンク132件（課題IDのアンカーを含む）、Skill必須項目・名前とディレクトリの一致、コードフェンス、文字化け、AGENTS.mdの65行を確認し、問題なし。

Cursorの5 mdcについてYAML構文と適用条件も確認し、検証用Pythonは終了コード0。移行したコード原則・UI本文・レビュー手順を元のルールと照合し、レビュー担当による無断修正を実装担当への返却に変更した。これは今回承認された役割分担への整合。

git status --shortは再確認でも非ゼロ終了（not a git repository）。Git差分・コミットに基づく検証は実施不能としてISS-004を維持する。文書・Skillsのみの変更のため、アプリの型・ビルド・実機テストは対象外で未実行。依存導入は行っていない。

実装セッションの確認は自己確認であり、独立レビューは[ISS-010](../quality/issues.md#iss-010)で未実施として管理する。両クライアント実機互換性と独立レビューが未完了のため、Phase 2全体や公開準備が完了したとは判定しない。
