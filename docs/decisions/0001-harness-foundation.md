# ADR 0001: 既存拡張へ段階的にハーネスを導入する

- 日付: 2026-11-14
- 状態: 方針採用、Phase 0〜2の整備着手。後続ツール選定・環境設定は未実施。
- 根拠: ユーザーが現行資産の利用、TypeScript + WXT + pnpm継続、個人開発・GitHub・ストア公開を確認し、提示した設計の実装を依頼。

## 背景

既存実装・PRD・設定一覧・Cursorルールがある一方、共通入口、独立レビュー手順、統合検証、CIが不足する。新規プロジェクトとして作り直さず、正本と実装済み範囲を明確にする。

## 決定

- 既存技術・ソース・仕様書を保持。短いAGENTS.mdから共通文書へ誘導する。
- 共通手順は.agents/skillsへ置き、初期は5 Skillsに限定する。Cursorルールには製品固有の適用と参照だけを残す。
- 実装と独立レビューは別セッション。レビュー担当は明示許可なしにソースを修正しない。
- Phase 0〜2は文書・Skills。自動検証・CI・E2Eは後続フェーズで導入し、未導入を成功と記録しない。
- 個人の最終判断でマージ・公開。自動提出、外部契約、費用、シークレット登録は別の明示許可。
- 未決定の要件と既存文書の矛盾は問題台帳へ残し、独断で解消しない。

## 代替案とトレードオフ

- 既存Cursorルールのみ: 変更量は少ないが、別製品で知識が共有されない。
- 全手順をAGENTSへ集約: 読み込みが容易な一方、肥大化と文書重複を招く。
- 全13 SkillsとCI/E2Eを一括導入: 初期負荷・依存・未確認の制約が大きい。

採用案は文書の参照関係を増やすため、リンクと鮮度の確認が必要。文書整備だけでは品質ゲートを強制できない。

## 追記（2026-11-19）

実サイト実機レビュー用に 6 つ目の Skill `real-site-review` を追加した。Chrome / Firefox 共通の `results.json` 形式と `check:real-site`（通常 verify 外）を伴う。初期5 Skills限定は基盤導入時の方針であり、実機証跡の手順追加を禁ずるものではない。新外部 MCP の必須化や verify への実サイト混入は別判断とする。

## 再検討条件

チーム化、macOS保証、対象サイト拡大、自動提出、計測基準確定、Skills実機互換性の問題が発生した場合は新ADRで変更する。元の判断履歴を消さない。
