## 1. プロダクト目標

全画面視聴中でも、コメントを **読む・書く・ノイズを減らす** を、映像を大きく犠牲にせず行える。

YouTube（ライブ／アーカイブ／通常スレッド）と Twitch（ライブ／VOD）で、同じ拡張・近い操作感を提供する。

---

## 2. ターゲットユーザー

- 配信・アーカイブを全画面またはシアターで見る視聴者
- デュアルモニタで別窓チャットを使う視聴者
- ニコ動風弾幕表示を好むが、必要時は入力もしたい視聴者
- Chromium 系または Firefox を使い、ストアから入れたいユーザー

非ターゲット（MVP）: 配信者の OBS オーバーレイ用途、モバイル、モデレーション業務の完全代替

---

## 3. MVP スコープ

### 3.1 対応サイト・コンテンツ

| コンテンツ | MVP | 備考 |
|------------|-----|------|
| YouTube Live / プレミア | ○ | ライブチャット。チャット可の待機室も含む（ISS-020） |
| YouTube アーカイブ（チャットリプレイ） | ○ | 再生位置同期 |
| YouTube 通常動画（スレッド型コメント） | ○ | **別アダプタ**。弾幕は使わない。Shorts は実装可だが受け入れ必須ではない |
| Twitch ライブ | ○ | |
| Twitch VOD（チャットリプレイ） | ○ | 再生位置同期。Highlights が `/videos/` 同経路なら含む。公式別窓／埋め込み iframe は無し（自前リスト） |
| Twitch 第三者エモート | ○（Phase 12） | BTTV / FFZ / 7TV（オフ可） |
| Super Chat / Cheer / レイド等の **表示** | ○ | 送信・課金 UI は Post-MVP（ISS-020） |
| ニコニコ生放送 | × | 2026-11-15 にスコープ外へ。再導入は別 ISS |
| Kick 他 | × | Post-MVP |
| Twitch クリップ / ミニプレイヤー追従 | × | ISS-020 で対象外（破綻しないことのみ） |

パターン正本: [content-patterns-2026-11-15.md](./quality/content-patterns-2026-11-15.md)

### 3.2 表示モード（ユーザーが選択）

| モード | MVP | 通常 YT コメント | ライブ／Twitch |
|--------|-----|------------------|----------------|
| オーバーレイパネル（積み上げ） | ○ 本番品質 | ○ | ○ |
| 別ウィンドウ（ポップアウト） | ○ 本番品質 | **Post-MVP**（パネル必須） | ○ |
| 弾幕（右→左） | ○ | **無効** | ○（トグル） |

パネルと弾幕の同時表示は MVP では「どちらか主＋弾幕はオプション重ね」を許容する。設定で明示する。

### 3.3 投稿

- MVP: 通常チャット／通常コメントの **送信**
- 可能ならネイティブ入力の再利用または転送（ToS・絵文字・認証の一貫性のため）
- 通常 YT コメント: パネルから公式返信 UI への返信（Phase 14）
- Post-MVP: スーパーチャット／Cheer の **送信**、深いスレッド UI、モデ操作、チャンネルポイント自動回収（表示は §3.1）

### 3.4 NG / フィルタ（MVP）

全表示モードに横断適用する。

| 機能 | MVP |
|------|-----|
| NG ワード（部分一致、任意で正規表現） | ○ |
| ユーザー除外（表示名 / チャンネル ID 相当） | ○ |
| Bot・`!command` 除外 | ○（任意トグル） |
| ロール優先（モデ／メンバー等を間引き対象外） | ○（簡易） |
| 翻訳・AI 要約 | × |

### 3.5 設定・操作（MVP）

- 表示 ON/OFF、モード切替
- パネル位置・サイズ・透明度・フォントサイズ
- 弾幕: 速度、不透明度、密度／行数、縁取り
- 別窓: 位置・サイズ記憶
- ショートカットで表示トグル／モード切替
- 保存先: `storage.local`（端末ローカル）。同期は任意・Post-MVP 可
- UI 言語: `auto` + 約 44 言語（`AppLocale` / `locale-meta.ts`）。不足キーは英語フォールバック

詳細一覧: [settings-inventory.md](./settings-inventory.md)

### 3.6 プライバシー

- チャット／コメント本文を開発者サーバへ送らない
- アカウント不要
- アナリティクス SDK を MVP に入れない
- ストア用プライバシーポリシーを公開必須

## 4. 明示的非スコープ（Post-MVP / 対象外）

- Kick 等の追加プラットフォーム
- ニコニコ生放送（旧 Phase 10–13 実装は 2026-11-15 に削除）
- OBS / 配信者向けブラウザソース
- 翻訳、AI 要約・キャラチャット
- チャンネルポイント／Drops 自動回収を売りにする機能
- モバイルブラウザ
- 通常コメントへの弾幕適用
- 通常 YT コメントの別ウィンドウ（MVP はパネルのみ）
- Shorts を受け入れ必須とすること（実装ベストエフォートは可）
- Twitch クリップ、ミニプレイヤー／ブラウザ映像 PiP への追従
- メンバー／サブ未加入時のゲート突破
- マルチチャンネル同時視聴の統合タイムライン（別窓を複数開くのは Popout の自然な結果として許容）

## 5. ギャップトップ10 → 要件マッピング

| # | 足りない体験 | MVP での応え方 |
|---|--------------|----------------|
| 1 | YT と Twitch で拡張が分断 | 両サイトを同一拡張・同一設定モデルでカバー |
| 2 | 読むモードと書くモードが同居しない | パネル／別窓で投稿、弾幕は読む専用オプション |
| 3 | 通常 YT コメントが統合されない | `YouTubeVideoComments` アダプタ（MVP はパネル。別窓は Post-MVP） |
| 4 | NG がモード横断でない | Filter を Core に置き自前 View 全体へ適用。公式埋め込みは `applyToNativeChat`（既定 ON） |
| 5 | 別窓とオーバーレイの切替が面倒 | 表示モードを設定＋ショートカットで切替、位置を記憶 |
| 6 | チャット閉時の受信と投稿パネルの両立 | 受信経路と入力 UI を分離設計（隠し受信＋ネイティブ入力流用を検証） |
| 7 | アーカイブ同期の説明不能 | 同期を MVP 受け入れ条件にし、ズレ許容を設定（秒）で明示 |
| 8 | Firefox / Chromium 機能差 | 両ストアを目標。差異は機能フラグで文書化、MVP で意図的な削りは最小 |
| 9 | 高密度時の間引き | 表示上限・間引き＋ロール優先 |
| 10 | プライバシー＋OSS＋ストアの両立 | 最小権限、MIT 想定の自前コア、ポリシー文書 |

## 6. 通常 YT コメント（別系統）詳細

ライブチャットと **データモデル・UI・取得経路を分離** する。

必須（MVP）:

- 全画面時にスレッド一覧をオーバーレイ（パネル）で表示
- 投稿・返信（ネイティブ UI 再利用優先）
- 並び（人気／新しい順）の踏襲または切替
- 「続きを読み込む」相当
- 弾幕モードは選択不可（UI で無効化）

Post-MVP: 通常コメントの別ウィンドウ表示

参考競合: Youtube Comment Viewer（体験ベンチマーク。コード流用はライセンス確認後）

---

## 7. 非機能要件

- Adapter 単位でサイト DOM 差分を隔離。セレクタ複数・壊れ検知
- Fullscreen API: オーバーレイを全画面要素配下へ再配置
- 高負荷時の表示上限・間引き
- Manifest V3、WebExtensions 互換（Chromium + Firefox）
- ストア審査: ホスト権限は **視聴・機能に必要な明示ホストのみ**（`<all_urls>` 禁止）
  - **必須**: `youtube.com` / `www.youtube.com`、`twitch.tv` / `www.twitch.tv`
  - **条件付き**（`twitch.thirdPartyEmotes` が ON のとき）: BTTV / FFZ / 7TV の API・CDN
  - 権限 API: `storage`、`windows`（別窓）
- 弾幕機能について、日本向けストア説明／README に非営利・非侵害の免責を明記（競合慣行）

## 8. アーキテクチャ制約（実装時）

```
SiteAdapters (YTLive | YTComment | Twitch)
    → NormalizeMessage → NGFilter → DisplayRouter
        → OverlayPanel | Danmaku | PopoutWindow
```

- 投稿: ネイティブ入力の再利用／転送を優先
- 通常コメント経路では Danmaku を Router が無効化

実装方針の判定: [build-or-fork.md](./build-or-fork.md)

## 9. 受け入れ基準（MVP 完了の定義）

1. YT ライブ／プレミア（チャット可の待機室含む）全画面でパネル表示・投稿・NG が動作する
2. Twitch ライブ全画面で同様に動作する
3. 弾幕トグルがライブ／Twitch で動作する（通常コメントでは出ない）
4. ライブ系（YT／Twitch）で別窓表示と位置記憶ができる
5. YT アーカイブでシーク後もチャットがおおむね追従する（許容ズレは設定またはドキュメントで定義）
6. Twitch VOD（Highlights 同経路含む）で再生・シーク後もチャットがおおむね追従する（同上。公式別窓／埋め込みは対象外）
7. 通常 YT 動画全画面でスレッド閲覧・投稿ができる（パネル。別窓は Post-MVP。Shorts は必須ではない）
8. Super Chat／Cheer／レイド等の **表示** がパネル／弾幕で落ちない（送信は不要）
9. Chrome と Firefox の両方で上記の主パスが通る
10. プライバシーポリシーと最小権限でストアスキャン／自己チェックを通過できる状態

詳細母集団: [content-patterns-2026-11-15.md](./quality/content-patterns-2026-11-15.md)
