# YouTube / Twitch コンテンツパターン（完全対応の定義）

状態: **オーナー承認済み（2026-11-15）** — ISS-020。  
目的: 「YT と Twitch を完全対応」と言うときの **含める／切る** を一枚に固定し、実サイト検証の母集団にする。  
関連: [PRD](../prd.md)、[実サイトチェックリスト](site-verification-checklist-2026-11-15.md)、[release](../operations/release.md)。

判定記号（実装・検証の記録用）: ✅ 合格　⚠️ 条件付き　❌ 失敗　⏭ 未実施　N/A 対象外

---

## 完全対応の定義（要約）

**必須コア**

- YouTube: ライブ／プレミア（チャットがある待機室含む）／チャットリプレイ付きアーカイブ／通常動画コメント（パネル）
- Twitch: ライブ／VOD アーカイブ（Highlights が `/videos/` 同経路なら含む）
- 課金・通知系は **表示のみ**（Super Chat / Sticker / Cheer / レイド等）。送信・課金 UI は対象外
- プレイヤー: 通常・シアター・全画面。Chrome と Firefox
- メンバー／サブ限定: **ログイン済みで視聴・チャットできる場合のみ** 必須。未加入ゲートは突破しない

**明示的に切る（受け入れ必須にしない）**

- Shorts の合格必須化（実装が動いても可）
- Twitch クリップ
- ミニプレイヤー／ブラウザ映像 PiP への追従
- モバイルホスト（`m.youtube.com` 等）
- 埋め込みプレイヤー単独ページ、Studio／ダッシュボード
- Super Chat / Cheer 等の **送信**

## 実装メモ（観測事実）

- YouTube live adapter は `yt-live-chat-paid-message-renderer` を監視対象に含む（Super Chat 表示経路あり）。Sticker／メンバー加入行の網羅は要実機。
- Twitch Cheer／レイド行の専用正規化は薄い可能性あり → 表示必須のギャップとして実機で確認し、欠ければ実装課題へ。
- Shorts は `isYouTubeWatchWithComments` で通常コメント経路になり得るが、受け入れ必須ではない。
