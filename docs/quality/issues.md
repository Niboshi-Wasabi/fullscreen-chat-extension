- 対応: background の `windows.onRemoved` で管理中の窓だと分かったら `displayMode` をパネルにする。service worker が再起動したあとは session storage の記録で見分ける。拡張側から閉じるときは先に記録を消すので対象外。Document PiP の窓を利用者が閉じたときも同じくパネルへ戻す。ページ離脱で閉じたときは戻さない。
- 影響: 別窓を開いたままブラウザを終了すると、次回は表示モードがパネルになりうる。回帰は `background-popout` と `runtime-lifetime` に追加した。
- 解決条件: 両ブラウザで別窓を閉じるとパネルが動画上に戻り、別窓が再び開かないこと。
- 実機で見つかった追加の不具合（Chrome 157）: 常に前面オンのままポップアップから別窓にすると、PiP が断られて通常の別窓になる。この別窓を × で閉じても表示モードが別窓のまま残った。原因は推測を含めて二つ。一つ目は、ページ側がフォーカスのたびに PiP を試し直して通常別窓を閉じ、それを利用者が閉じたものと区別できなかったこと。二つ目は、`windows.onRemoved` より先にページ側の開く要求が届くと、background が閉じた窓の記録を捨てて開き直していたこと。
- 追加の対応: ページ側は PiP が断られたら、表示モードが変わるまで通常別窓を保つ。background は開く要求の前に記録した窓の存在を確かめ、消えていればパネルへ戻して開かない（`forgetUserClosedPopout`）。回帰は `runtime-lifetime`（フォーカスで通常別窓を保つ）と `background-popout`（開く要求が先に届いてもパネルへ戻る）に追加した。
- 実機（2026-11-18、未ログイン、`twitch.tv/xqc`）: Chrome 157 と Firefox 160 で、修正後のビルドを使った。PiP の × と通常別窓の × のどちらでも、動画上にパネルが戻り、別窓は開き直さず、ポップアップの表示モードはパネルになった。本体をクリックしても通常別窓は残った。Chrome では、ポップアップでパネルに戻すと別窓が閉じることも確かめた。Firefox の修正前は、× を二回押さないと閉じなかった。修正後は一回で閉じた。証跡は両ブラウザの同日記録。
- 独立レビュー後の修正（2026-11-19）: 利用者が PiP を閉じたあと、パネルへの切替が届く前にフォーカスが来ても、PiP を求め直さず、代わりの通常別窓も開かない。表示モードが変わるか、もう一度「前面に固定」を押すまで抑える。回帰は `pip-chat`（`close()` では閉じたと報告しない）と `runtime-lifetime`（停止後やページ離脱中に届いた報告ではパネルへ戻さない）に追加した。ページ離脱で PiP が閉じたときは `pip-chat` も閉じたと報告するので、無視するのは `site-runtime` 側。
- 実機再確認（2026-11-19、未ログイン、`twitch.tv/xqc`、Chrome／Firefox）: 「前面に固定」で Document PiP が開いた。PiP 文書を外部クローズしたあと視聴タブへフォーカスしても PiP／通常別窓は開き直さず、動画上のパネルが戻った（RL-031b）。ポップアップでパネルへ切り替えると PiP は `close()` 経路で閉じ、パネルに戻った（RL-033b）。証跡は `rl-031b-033b-2026-11-19-chrome` と `rl-031b-033b-2026-11-19-firefox-2`。人間の承認は未実施。

## ISS-032

- 種類・状態: 不具合・仕様変更 / **修正済み・実機確認済み（2026-11-18）。全画面中の操作は未実施。独立レビューの指摘を修正し、再レビューで Critical・Major・Minor 0（2026-11-19）。修正分の実機確認と人間の承認は未実施。**
- 根拠: 「常に前面」をオンにしても、Firefox と Chrome の両方で普通の別窓になった。Firefox には Document PiP が無い（この推測は誤り。下の訂正を参照）。Chrome でも、Document PiP はその動画ページでのクリックが要るのに、ツールバーのポップアップから開こうとしていた（Chrome での原因の切り分けは推測）。証跡は両ブラウザの同日記録。
- 判断: オーナー（2026-11-18）。動画ページ内のパネルに「前面に固定」を置き、そのクリックで Document PiP を開く。Firefox ではスイッチを使えない表示にして理由を出す。
- 対応: `alwaysOnTop` がオンで Document PiP があるとき、パネルの歯車メニューに「前面に固定」を出す。押すとクリックの中で PiP を要求し、表示モードを別窓にする。オプションは Document PiP が無いとスイッチを無効にし、説明を差し替える。PiP が開けなかったときは従来どおり通常の別窓になる。
- 未確認: 全画面中に押したときの挙動（拡張オプションページでの判定は両ブラウザの実機で確認済み）。新しい文言の英日以外は英語のまま（`locale-fallbacks.json` に登録）。
- 解決条件（当初）: Chrome でボタンから枠の無い前面固定の窓が開き、閉じるとパネルに戻ること。Firefox ではボタンが出ず、オプションのスイッチが無効で理由が読めること。
- 訂正（2026-11-18）: Firefox 160 の実機では `documentPictureInPicture` があり、「Pin on top」から PiP が開いて本体より前に残った。最初に普通の別窓になったのは、ポップアップから開いてページ上の操作が無かったため。オーナー判断（2026-11-18）で、ブラウザ名ではなく機能の有無で判定する今の実装を保つ。無効表示の文言はブラウザ名を出さない形にした。
- 解決条件（改訂）: Document PiP があるブラウザでは、ボタンから前面固定の窓が開き、閉じるとパネルに戻ること。無いブラウザではボタンが出ず、オプションのスイッチが無効で理由が読めること。
- 実機（2026-11-18、未ログイン、`twitch.tv/xqc`）: Chrome 157 では「前面に固定」から `twitch.tv` の小窓が開いた。Win32 で見ると、小窓だけが最前面だった。Firefox 160 では「Pin on top」から小窓が開き、本体をクリックしても上に残った。どちらも × でパネルに戻った。Firefox では常に前面オフのとき歯車メニューにボタンが無かった（Chrome は未確認）。オプションのスイッチは両ブラウザとも押せた。Document PiP が無いブラウザでの無効表示は、対象のブラウザが手元に無く未確認。証跡は両ブラウザの同日記録。

## ISS-033

- 種類・状態: 不具合 / **修正済み・実機確認済み（2026-11-18）。独立レビューの指摘を修正し、再レビューで Critical・Major・Minor 0（2026-11-19）。修正分の実機確認と人間の承認は未実施。**
- 根拠: Firefox 160 の実機で、Twitch のページ側チャット欄を折りたたんでいるあいだ、Document PiP の一覧が空だった。ページ側を開くと流れ始めた。Twitch のアダプタはページ側の DOM からメッセージを読むため。

- 解決条件: 公式チャット UI がオンで、Twitch のページ側を折りたたんでも PiP にチャットが出ること。
- 実機（2026-11-18、未ログイン、`twitch.tv/xqc`）: ページ側を折りたたんだまま、Chrome 157 と Firefox 160 の PiP に Twitch の公式チャットが出て流れた。YouTube ライブとリプレイの PiP は実機で試していない。証跡は両ブラウザの同日記録。
