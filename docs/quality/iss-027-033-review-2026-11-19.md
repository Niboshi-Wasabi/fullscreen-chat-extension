# ISS-027〜033 独立レビュー（2026-11-19）

## 対象

- 依頼・関連要件: ISS-027（通常 YouTube 動画コメントの廃止）、ISS-028・029（別窓の所有、ページ側チャット欄）、ISS-030〜033（別窓の既定キー、閉じたらパネルへ、前面固定、PiP の公式チャット）。[問題台帳](issues.md)、[通常YTコメント廃止計画](../plans/2026-11-16-remove-youtube-comments.md)、[別窓見直し計画](../plans/2026-11-18-popout-close-and-pin.md)、[PRD](../prd.md)、[設定一覧](../settings-inventory.md)。
- 比較元 / 対象: HEAD `889116b`（ブランチ `feat/iss-026-comments-portal`）と未コミットの作業ツリー（変更 113 件、未追跡 14 件）。
- 独立性: 実装担当とは別セッションのエージェント3体が、範囲を分けて担当した。担当A は ISS-030〜033、担当B は ISS-028・029、担当C は ISS-027 とそれ以外。どれも同じ製品（Cursor）上で動き、実装担当と同じモデル系統の可能性がある。人間による独立レビューの代わりにはならない。実装担当の説明は渡さず、差分・コード・仕様を直接読ませた。
- 変更の禁止: 3体ともリポジトリ内のファイルを変更していない。レビューの前後で `git status --short` は 127 行のまま。この記録は実装担当がレビュー結果を写したもの。

## 指摘

Major 3、Minor 12、Nit 10。Major と Minor はすべてコードを読んで導いたもので、実機では再現していない。推測を含むものは推測と書く。

### Major

1. **YouTube の厳格なライブ判定が緩んだ可能性（担当C）**。`src/shared/youtube-page.ts` の `isYouTubeLiveNowStrict`、`LIVE_UI_SELECTOR`、`hasVisibleLiveUi`。`.ytp-live-badge` の `disabled` 判定を外し、範囲を絞らないバッジも代わりに残している。URL パスは確認せず、`#primary` 配下のライブバッジがあればライブとみなす。関連動画やホームのライブのサムネイル、`disabled` バッジの残る終了配信で、通常動画なのにライブの処理と隠し iframe が起動する恐れがある（推測。ISS-021 と同じ症状）。否定ケースのテストが無い。方針: `/watch`・`/live/` に限り、判定範囲をプレーヤーと動画メタデータに絞る。否定テストと実サイト確認を足す。
2. **2つのウィンドウを並べると、前のウィンドウへ戻っても別窓の URL が戻らない（担当B）**。`src/app/site-runtime.ts` の `onBecomeForeground`・`syncPopout`、`src/views/popout/index.ts` の `sync`。隠れていないタブは `lastPopoutDesired` が `true` のままで、`sync()` は覚えている URL が同じなら何もしない。そのため、別のウィンドウのタブに別窓を取られたあと元のウィンドウへ戻っても、URL が戻らない。ISS-028 の仕様に反する。方針: フォーカスで所有を取り直す要求を送る。別タブに取られたら覚えた URL を捨てる。
3. **視聴タブに戻るたびに別窓がフォーカスを奪う（担当B）**。`site-runtime.ts` の可視化処理、`src/entrypoints/background.ts` の `windows.update(..., { focused: true })`。見えたタブは `popout.open()` を送る。background は URL が同じでも別窓にフォーカスを移す。今回の差分で入った挙動で、タブへ戻った直後のキー入力が別窓へ行く。方針: 明示的な操作のときだけフォーカスし、所有の移動では URL が違うときだけ更新する。

### Minor

1. **PiP を閉じた直後のフォーカスで、通常の別窓が残る可能性（担当A、推測）**。`site-runtime.ts` の `onClosedExternally`、`onBecomeForeground`、PiP 失敗時のフォールバック。パネルへの保存が戻る前に `focus` が届くと、PiP を要求して断られ、通常別窓を開きうる。その後パネルに切り替わっても、窓を作り終える前だと閉じる要求が出ない。方針: 利用者が PiP を閉じたら、表示モードが変わるまで PiP もフォールバックも抑える。回帰テストも足す。
2. **PiP の閉じ方を区別する経路にテストが無い（担当A）**。`src/views/pip-chat/index.ts` の pagehide と `close()`、`site-runtime.ts`。`runtime-lifetime` は `pip-chat` を差し替えて `onClosedExternally` を直接呼ぶだけ。`close()`・`dispose`・ページ離脱では呼ばれないことを誰も確かめていない。実際にページ離脱を守っているのは `bindPageLifecycle` が先に dispose することで、`pageUnloading` ではない。
3. **ストア掲載文に P（別窓）のショートカットが残る（担当A）**。`docs/store-listing.md` の 44 行と 74 行。
4. **PRD の追記段落が表示モードの表を分断した（担当A）**。`docs/prd.md` の 54 行目の段落が表の行の間に入り、弾幕の行が表から外れた。
5. **service worker 再起動直後は、ショートカットが所有者のタブへ届かない（担当B）**。`background.ts` の `forwardCommandToActiveTab`。`managed` を復元する前に転送先を決める。所有者のタブを閉じても `ownerTabId` が残る。方針: 転送前に復元を待つ。必要なら `tabs.onRemoved` で消す。テストを足す。
6. **「非表示」を展開ラベルと誤判定する（担当B）**。`src/shared/page-chat-column.ts` の `isChatColumnExpandLabel` が「表示」を含むかを先に見るので、「非表示」でも展開とみなす。`src/adapters/twitch/index.ts` の `isExpandedToggle` は重複している。今の日本語表記では起きない。
7. **ISS-028・029 の主な経路に回帰テストが足りない（担当B）**。実行部側の所有の取り直し、裏タブからの `close` の拒否、ポップアップ型ウィンドウからの `open` の拒否、欄の開閉や全画面でのパネル付け外し、Twitch の欄クラスでの判断。YouTube の「閉じている」テストは条件が二つ重なっている。
8. **旧版の設定バックアップが読み込めない（担当C）**。`src/shared/settings-backup.ts`、`settings-validation.ts`。旧版の書き出しには `youtubeComments` が入り、未知のキーとして拒否される。storage の互換性は保たれている。未公開版なので影響は開発者とテスターに限られる。方針: 廃止キーだけ取り除いてから検証する。または互換性を切る判断を記録する。
9. **起動に失敗するとプレーヤーボタンが残る（担当C）**。`src/entrypoints/content.ts` で `startPlayerChrome` のあとに `await startYouTubeLiveRuntime` を待つ。失敗したときに `stopPlayerChrome()` が呼ばれない。
10. **「任意ページ」設定だと通常動画でも公式チャット別窓が開く（担当C）**。`src/shared/site-ids.ts` の `openPolicy: "anyWatchPage"`。通常動画では動かないという仕様と食い違う。設定一覧の既定値の説明も、チャットリプレイを含む実装とずれている。
11. **廃止機能のコード・文書が残る（担当C）**。`src/core/router.ts` の `danmakuAllowed`・`popoutAllowed`（常に true で未使用）、`overlay-panel` の `"replyable"` 分岐、`youtube-page.ts` の古いコメント、`docs/architecture/contracts.md` の返信先の記述。
12. **`.cursor/mcp.json`（未追跡）の扱いが未決定（担当C）**。秘密情報は無い。ユーザー名を含む絶対パスがあり、`npx -y …@latest` で最新版を起動する。gitignore にも文書にも扱いの記載が無い。

### Nit

- 担当A: 前面固定の直後に `dispose` が走ると PiP が残る余地（`dispose` の条件を `lastPipDesired || pipChat.isOpen()` に）。background のコメントと例外時の処理のずれ。再起動後のテストが session 記録だけの経路を区別できていない。`closeInternal` の未使用引数。Document PiP の判定方法が2つある。
- 担当B: 「隠れたら所有を手放す」の記述と実装のずれ。公式チャットが使えず自前一覧になった場合も表示を制限する。パネルを外しているあいだ `toggle-compose-focus` が何もしない。
- 担当C: `parseClockToSeconds` の再 export。隠しライブチャット iframe の ID の文字列直書き。`runtime-lifetime` のモックに残る削除済みメソッド。
